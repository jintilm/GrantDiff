# GrantDiff v1.0.0-rc.1

This candidate prepares GrantDiff's Kubernetes RBAC review commands for v1.0 with a documented support and compatibility contract. Windows x86-64 and Linux x86-64 archives include the executable, four example scenarios, expected controller reports, schemas, licenses and validation records.

## Changes

- Verify the full RBAC/identity and resource-catalog files in new snapshot schema 1.1. Legacy schema 1.0 snapshots retain their documented read compatibility.
- Require explicit empty-after acknowledgement when candidate operations delete all RBAC objects.
- Handle Windows short working-directory aliases consistently when checking input directory boundaries.
- Include pinned kube-state-metrics v2.14.0 configuration demonstrating the effect of revoking Secret observation, alongside the existing ExternalDNS permission-addition example.
- Automate archive checksums, extracted native execution, JSON Schema 1.0, CLI failure codes and Windows/Linux output comparisons.
- Gate tagged releases on the full unit, Kubernetes and package verification workflow, then upload the verified archives and SHA-256 checksums.

## Try the candidate

Extract the archive for your platform and open a terminal in that directory. Linux uses `./grantdiff`, and Windows uses `./grantdiff.exe`.

```text
./grantdiff version
./grantdiff diff --before examples/retained/before --after examples/retained/after --identities examples/retained/identities.yaml --catalog examples/retained/catalog.yaml
./grantdiff diff --before examples/external-dns/before --after examples/external-dns/after --catalog examples/external-dns/catalog.yaml --compact --summary --fail-on high
```

The retained-access case explains the remaining group binding. The ExternalDNS command returns code 1 because the hypothetical candidate adds high-risk Secret reads. Both cases run locally from the extracted archive.

## Candidate boundaries

The candidate contract covers native Kubernetes RBAC and the tested Windows/Linux x86-64 environments. User group membership needs explicit data, cyclic aggregation produces incomplete results, and wide wildcard workloads remain bounded by the comparison budget. Compact mode preserves complete evidence using schema 1.0 selectors. See the compatibility document for snapshot integrity, output and versioning details.

Finite generated-policy samples and fixed benchmark workloads describe the measured cases. Feedback from outside users remains part of the path to the stable release. Reports of unexpected conclusions should include the version, input scope, minimal policy/identity/catalog inputs and the resulting report.
